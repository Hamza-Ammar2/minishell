================================================================================
                        MINISHELL TASK DIVISION PLAN
================================================================================

This document suggests ways to divide work between two team members for the
minishell project. Adapt based on your strengths and preferences.


================================================================================
                            DIVISION STRATEGY
================================================================================

There are several ways to divide the work:

OPTION 1: Horizontal Division (By Stage) - RECOMMENDED FOR YOUR TEAM
----------------------------------------------------------------------
One person handles structure/parsing, the other handles logic/execution.

Person A: Structure & Details (Parsing, Syntax, Signals)
  - Main loop and readline integration
  - Lexer/Tokenizer
  - Parser
  - Quote handling and syntax validation
  - Signal handling

Person B: Logic & Algorithms (Execution, Process Management)
  - Executor (fork, execve, process management)
  - Variable expansion (algorithmic logic)
  - Built-in commands
  - Environment management
  - Pipe and redirection setup (fd manipulation)


OPTION 2: Vertical Division (By Feature)
-----------------------------------------
Each person implements complete features end-to-end.

Person A:
  - Basic command execution (lexer → parser → executor)
  - Built-ins: echo, pwd, env
  - Simple redirections (>, <)

Person B:
  - Pipes implementation
  - Built-ins: cd, export, unset, exit
  - Advanced redirections (>>, <<)


OPTION 3: Core + Enhancement
-----------------------------
One person builds the core, the other adds features.

Person A: Core Shell
  - Main loop
  - Basic tokenizer
  - Simple executor (external commands only)
  - Basic error handling

Person B: Features
  - All built-in commands
  - Quote handling
  - Variable expansion
  - Pipes and redirections


RECOMMENDED: Option 1 (Customized for Your Team)
-------------------------------------------------
Person A focuses on parsing/structure/details.
Person B focuses on execution logic/algorithms.
Start together on core, then divide as outlined above, integrate regularly.

================================================================================
                            INTERFACE CONTRACTS
================================================================================

Define clear interfaces between modules:

TOKENIZER → PARSER (Person A)
------------------------------
Input: char *input (raw string)
Output: t_token *tokens (linked list)
Contract:
  - Tokenizer creates all tokens
  - Handles quote detection (marks quote type)
  - Returns NULL on allocation error


PARSER → EXPANDER (Person A → Person B)
----------------------------------------
Input: t_token *tokens (linked list)
Output: t_command *commands (linked list)
Contract:
  - Parser validates syntax
  - Parser builds command structure
  - Parser returns NULL on syntax error
  - Expander receives parsed commands


EXPANDER → EXECUTOR (Person B)
-------------------------------
-------------------
Input: t_command *commands, t_shell *shell
Output: int exit_status
Contract:
  - Executor frees commands after use
  - Executor updates shell->exit_status
  - Executor handles all errors


ENVIRONMENT MODULE
------------------
Functions:
  - char *env_get(t_env *env, char *key)
  - void env_set(t_env **env, char *key, char *value)
  - void env_unset(t_env **env, char *key)
  - char **env_to_array(t_env *env)
Contract:
  - env_get returns NULL if not found
  - env_set duplicates key and value
  - env_to_array allocates new array for execve
