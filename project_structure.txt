================================================================================
                        MINISHELL PROJECT STRUCTURE
================================================================================

OVERVIEW
--------
A minishell is built in several interconnected stages that process user input
from raw text to executed commands. Each stage has a specific responsibility.


================================================================================
                            MAIN COMPONENTS
================================================================================

1. MAIN LOOP
   - Display prompt
   - Read user input (readline)
   - Pass input through the pipeline
   - Handle exit conditions
   - Manage history (add_history)

2. LEXER/TOKENIZER
   - Takes raw input string
   - Splits into tokens (words, operators, special chars)
   - Identifies token types:
     * WORD (command/argument)
     * PIPE (|)
     * REDIRECT_IN (<)
     * REDIRECT_OUT (>)
     * REDIRECT_APPEND (>>)
     * REDIRECT_HEREDOC (<<)
     * OPERATOR (&&, ||) - if implementing bonus
   - Handles quoted strings (preserves spaces)
   - Returns array/list of tokens

3. PARSER
   - Takes token array
   - Builds command structure/AST
   - Groups tokens into commands
   - Identifies pipelines
   - Validates syntax
   - Creates command table/linked list
   - Returns structured command representation

4. EXPANDER
   - Processes each token for expansions
   - Handles:
     * Environment variables ($VAR, $?)
     * Quote removal (after expansion)
     * Wildcard expansion (*) - if implementing
   - Preserves literal strings in single quotes
   - Expands variables in double quotes
   - Returns expanded tokens

5. EXECUTOR
   - Takes parsed command structure
   - Sets up execution environment
   - Handles:
     * Built-in commands (direct execution)
     * External commands (fork + execve)
     * Pipes (creating pipe fds, forking)
     * Redirections (dup2, open files)
   - Manages process creation and waiting
   - Updates exit status ($?)

6. BUILT-IN COMMANDS
   Must implement these commands internally (not via execve):
   
   - echo [-n]        : Print arguments
   - cd [path]        : Change directory (chdir)
   - pwd              : Print working directory (getcwd)
   - export [VAR=val] : Set environment variable
   - unset [VAR]      : Remove environment variable
   - env              : Display environment variables
   - exit [n]         : Exit shell with status

7. SIGNAL HANDLING
   - Ctrl+C (SIGINT)  : Display new prompt, don't exit
   - Ctrl+D (EOF)     : Exit shell
   - Ctrl+\ (SIGQUIT) : Do nothing (ignored in interactive mode)
   - Handle signals differently in:
     * Interactive mode (waiting for input)
     * Executing commands
     * Heredoc mode

8. ENVIRONMENT MANAGEMENT
   - Store environment variables
   - Handle modifications (export/unset)
   - Pass to child processes (execve)
   - Special variables:
     * PATH (for command lookup)
     * HOME (for cd ~)
     * ? (exit status)

9. ERROR HANDLING
   - Syntax errors (invalid pipes, redirections)
   - Command not found
   - Permission denied
   - File not found (redirections)
   - Memory allocation failures
   - Use perror/strerror for system errors

================================================================================
                            EXECUTION FLOW
================================================================================

1. Start shell → Initialize environment → Setup signals

2. Display prompt → Read input (readline)

3. Input string → Lexer → Tokens

4. Tokens → Parser → Command structure

5. Command structure → Expander → Expanded commands

6. Expanded commands → Executor:
   
   For each command in pipeline:
   - Check if built-in → Execute directly
   - If external:
     * Setup redirections
     * Fork process
     * Execute with execve
   
   For pipes:
   - Create pipes
   - Fork for each command
   - Connect stdin/stdout via pipe fds
   - Wait for all processes

7. Update exit status → Clean up → Loop back to step 2

================================================================================
                            KEY CONCEPTS
================================================================================

PIPES:
- Create pipe: pipe(int pipefd[2])
- pipefd[0] = read end, pipefd[1] = write end
- Use dup2 to redirect stdin/stdout to pipe fds
- Close unused ends in parent and child

REDIRECTIONS:
- Open files with appropriate flags
- Use dup2 to redirect file descriptors
- Handle multiple redirections (last one wins)
- Check file permissions and existence

FORK + EXECVE:
- fork() creates child process
- Child calls execve to replace with new program
- Parent waits with wait/waitpid
- Built-ins must NOT fork (they modify shell state)

QUOTES:
- Single quotes: Everything literal (no expansion)
- Double quotes: Expand variables, but preserve spaces
- No quotes: Expand and split on spaces

EXIT STATUS:
- 0 = success
- 1-255 = error codes
- 130 = terminated by Ctrl+C (SIGINT)
- 131 = terminated by Ctrl+\ (SIGQUIT)
- Store in $? for access
