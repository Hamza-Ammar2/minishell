                        MEMORY LEAK FIXES DOCUMENTATION
                              January 21, 2026
================================================================================

SUMMARY
-------
Fixed critical memory leaks in variable expansion code (src/exec/utils_str.c)
that were causing hundreds of memory leaks during test execution.

IMPACT: Reduced memory leaks from hundreds to nearly zero while maintaining
        703/941 tests passing (75% pass rate).

================================================================================
                              ROOT CAUSE ANALYSIS
================================================================================

The memory leaks were concentrated in the variable expansion system, specifically
in three related functions: do_env(), join(), and expand_str().

The core issue: Temporary strings allocated during variable expansion ($?, $VAR)
were not being freed, causing accumulating leaks in every command that used
variable expansion.

================================================================================
                                THE FIXES
================================================================================

FIX #1: do_env() - Missing free() on early returns
---------------------------------------------------
FILE: src/exec/utils_str.c
LINES: 15, 17

PROBLEM:
When do_env() handled special cases like:
  - Invalid variable names ($@, $$, etc.) → returned "$" literal
  - Exit status ($?) → returned ft_itoa(exit_status)
  
The input 'str' parameter (allocated by caller with ft_substr or ft_strdup)
was never freed, causing a leak on every occurrence.

EXAMPLE LEAK SCENARIO:
  Command: echo "$?"
  1. expand_str() calls: do_env(shell, ft_substr(start+1, 0, 1))
  2. ft_substr() allocates "?" string (1 byte + null)
  3. do_env() sees str[0]=='?' and returns ft_itoa(0) immediately
  4. The "?" string is NEVER FREED → 2 byte leak

SOLUTION:
Added free(str) before all early returns:
  - Line 15: return (free(str), ft_strdup("$"));
  - Line 17: return (free(str), ft_itoa(shell->exit_status));

This ensures the input parameter is always freed regardless of code path.


FIX #2: join() - Only freed first parameter, leaked second
-----------------------------------------------------------
FILE: src/exec/utils_str.c
LINE: 42

PROBLEM:
The join() helper function combines two strings into one. Original code:
  1. Created new string with ft_strjoin(s1, s2)
  2. Freed s1 (the accumulated result)
  3. Returned new string
  4. BUT NEVER FREED s2!

Since expand_str() calls join() with newly allocated strings from do_env()
and ft_substr(), s2 would leak on every call.

EXAMPLE LEAK SCENARIO:
  Command: echo "hello$USER"
  1. res = join(NULL, ft_substr(str, 0, 5))    → creates "hello"
  2. res = join(res, do_env(...))              → do_env returns "john"
  3. join() combines "hello" + "john" → "hellojohn"
  4. join() frees "hello" (s1) but NOT "john" (s2) → LEAK!

SOLUTION:
Added free(s2) after ft_strjoin():
  free(s1);  // Free the accumulated result
  free(s2);  // Free the newly added string

Now both input strings are freed since a new combined string is returned.


FIX #3: expand_str() - NULL pointer dereference on empty suffix
----------------------------------------------------------------
FILE: src/exec/utils_str.c
LINE: 84-86

PROBLEM:
When variable expansion reached end of string with no remaining text:
  1. str = NULL (set on line 78 when no more text after last $VAR)
  2. Line 84: return (res = join(res, ft_strdup(str)), res);
  3. ft_strdup(NULL) → SEGMENTATION FAULT

This caused 82 test failures when the leak fixes were first applied.

EXAMPLE CRASH SCENARIO:
  Command: echo "$USER"
  1. expand_str processes entire string
  2. After expanding $USER, no text remains
  3. Sets str = NULL and breaks
  4. Tries ft_strdup(NULL) → CRASH

SOLUTION:
Added NULL check before joining remaining text:
  if (str)
      res = join(res, ft_strdup(str));
  return (res);

Only duplicates and joins remaining text if it actually exists.


FIX #4: expand_str() - Optimization to skip empty allocations
--------------------------------------------------------------
FILE: src/exec/utils_str.c
LINE: 72-73

PROBLEM:
When $ appeared at start of string (start - str == 0), code would:
  1. Call ft_substr(str, 0, 0) → allocate empty string ""
  2. Pass to join() which would then free it
  
Not a leak, but wasteful allocation/deallocation of empty strings.

SOLUTION:
Skip joining prefix when it would be empty:
  if (start - str > 0)
      res = join(res, ft_substr(str, 0, start - str));

Prevents unnecessary malloc/free cycles for empty strings.

================================================================================
                              MEMORY OWNERSHIP MODEL
================================================================================

After these fixes, the memory ownership model is clear:

1. do_env():
   - RECEIVES: Ownership of 'str' parameter (must free)
   - RETURNS: New allocated string (caller must free)
   
2. join():
   - RECEIVES: Ownership of both s1 and s2 (must free both)
   - RETURNS: New allocated string (caller must free)
   
3. expand_str():
   - RECEIVES: Borrowed pointer to 'str' (does NOT free)
   - RETURNS: New allocated string (caller must free)

This consistent ownership model prevents leaks and double-frees.
