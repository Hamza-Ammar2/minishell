WORD SPLITTING IMPLEMENTATION
=============================

WHAT IS WORD SPLITTING?
-----------------------
In bash, when a variable is expanded WITHOUT quotes, the result is split
on whitespace (IFS) into multiple words/arguments. This is called "word splitting."

Example:
  VAR="one two three"
  echo $VAR      -> echo receives 3 arguments: "one", "two", "three"
  echo "$VAR"    -> echo receives 1 argument: "one two three"

Before this fix, our minishell treated $VAR as a single argument regardless
of quotes, which is incorrect behavior.

IMPLEMENTATION APPROACH: Tokenize -> Expand -> Re-tokenize
-----------------------------------------------------------
The standard approach is:
1. TOKENIZE: Break input into tokens (already implemented)
2. EXPAND: Replace $VAR with its value
3. RE-TOKENIZE (Word Split): For unquoted expansions, split on whitespace

We chose "Option A" - a simpler approach where we expand each token and
split it if it was unquoted and contains whitespace after expansion.


FILES CHANGED
=============

1. NEW FILE: src/lexer/word_splitting.c
------------------------------------------
PURPOSE: Contains all word splitting logic in one place.

FUNCTIONS:
- has_whitespace(str): Helper to check if a string contains whitespace.
  WHY: We only split tokens that have whitespace in their expanded value.

- create_split_tokens(splits, tail): Creates a linked list of tokens from
  an array of strings (result of ft_split).
  WHY: After splitting "one two three" into ["one", "two", "three"],
  we need to convert each into a t_token for the parser.

- process_word_token(shell, tok, should_free): Core logic for a single token.
  WHY: This is where the actual word splitting decision happens:
    - If token was QUOTED (single or double quotes), NO splitting
    - If expanded value has no whitespace, NO splitting
    - Otherwise, SPLIT on whitespace into multiple tokens

- expand_and_split_tokens(shell, tokens): Main entry point.
  WHY: Called from process_input() after tokenize() but before parse().
  Iterates through all tokens, expands them, and splits unquoted ones.

HOW IT WORKS
============

BEFORE (broken):
  export VAR="a b c"
  echo $VAR
  -> Tokenizer creates: [echo] [$VAR]
  -> Expander (during exec) replaces: [echo] [a b c]
  -> echo receives 1 argument: "a b c"  <-- WRONG!

AFTER (fixed):
  export VAR="a b c"
  echo $VAR
  -> Tokenizer creates: [echo] [$VAR]
  -> expand_and_split_tokens():
     - Expands $VAR to "a b c"
     - Token was unquoted (QUOTE_NONE) and has whitespace
     - Splits into: [echo] [a] [b] [c]
  -> Parser receives 4 tokens
  -> echo receives 3 arguments: "a", "b", "c"  <-- CORRECT!

QUOTED CASE (should NOT split):
  echo "$VAR"
  -> Tokenizer creates: [echo] ["$VAR"] with quote_type=QUOTE_DOUBLE
  -> expand_and_split_tokens():
     - Expands $VAR to "a b c"
     - Token was quoted (QUOTE_DOUBLE) - NO SPLIT
     - Result: [echo] [a b c]
  -> echo receives 1 argument: "a b c"  <-- CORRECT!

SINGLE QUOTES (should NOT expand):
  echo '$VAR'
  -> Tokenizer creates: [echo] ['$VAR'] with quote_type=QUOTE_SINGLE
  -> expand_and_split_tokens():
     - Token is QUOTE_SINGLE, expand_str returns "$VAR" literally
     - No expansion, no split
     - Result: [echo] [$VAR]
  -> echo receives 1 argument: "$VAR"  <-- CORRECT!

NOTES
=====

- Word splitting only applies to WORD tokens (not operators like |, <, >)
- Single-quoted strings ('$VAR') don't expand at all (handled by expand_str)
- Double-quoted strings ("$VAR") expand but don't word-split
- Empty expansions ($UNDEFINED) are removed from the token list
- We use ft_split with ' ' as delimiter (IFS is space by default in minishell)
- IMPORTANT: All places that previously called expand_str during execution
  were modified to avoid double expansion
