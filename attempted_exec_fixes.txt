DETAILED CHANGES:

1. OUTPUT BUFFERING FIX (src/exec/builtins.c)
----------------------------------------------
PROBLEM: 
  Test failures on pwd and env commands showing output in wrong order.
  Example: "pwd; echo $?" would print echo output before pwd output.

ROOT CAUSE:
  printf() uses buffered I/O which can delay output. When mixed with 
  unbuffered write() calls from other parts of execution, output appears
  in wrong order.

SOLUTION:
  - Changed pwd() from printf() to write(STDOUT_FILENO, ...) at line 17
  - Changed env() from printf() to write(STDOUT_FILENO, ...) at line 64
  - Removed newline arg requirement check in pwd() (line 10)

IMPACT:
  Fixed tests 22-23 (pwd), multiple env tests
  

2. EMPTY VARIABLE EXPANSION FIX (src/exec/exec_func_utils.c)
-------------------------------------------------------------
PROBLEM:
  Segmentation fault when executing commands with undefined variables.
  Example: "$EMPTY" or "$UNDEFINED_VAR" would crash the shell.

ROOT CAUSE:
  wraper() function created args array but didn't handle case where variable
  expansion returns empty string. NULL pointer was added to args causing
  segfault in execution.

SOLUTION:
  - Modified wraper() to skip empty expanded tokens (line 89-103)
  - Separated loop index (i) from array index (j) to handle gaps
  - Added NULL check in check_builtin() for args[0] (line 48)
  - Free empty strings instead of adding them to array

IMPACT:
  Fixed tests 134-135 ($EMPTY variable tests)


3. EMPTY ARGS PROTECTION (src/exec/exec.c)
-------------------------------------------
PROBLEM:
  After variable expansion, if all tokens become empty, args[0] is NULL
  which crashes during command execution.

SOLUTION:
  Added NULL check in exec_single() before command execution (line 77):
  if (!args[0])
      close_child(fd), free_splits(args), exit(0);

IMPACT:
  Prevents crashes when all arguments expand to empty


4. COMMAND PATH RESOLUTION FIX (src/exec/utils.c)
--------------------------------------------------
PROBLEM:
  Non-executable files like "test_files" or "README.md" were being executed
  instead of searching PATH, resulting in wrong exit codes (0 instead of 127).

ROOT CAUSE:
  get_path() checked if command exists with access(cmd, F_OK) before PATH
  search. This matched ANY file, not just executables or paths.

SOLUTION:
  Changed condition from:
    if (access(cmd, F_OK) == 0)
  To:
    if (strchr(cmd, '/') && access(cmd, F_OK) == 0)
  
  Now only bypasses PATH search if command contains '/' (is a path).
  Added NULL check for when PATH is unset (line 40).

IMPACT:
  Fixed tests 140, 146 (test_files, README.md commands)


5. INTERACTIVE MODE DETECTION (src/main.c)

  - Only print "exit" when is_interactive is true (line 98)

IMPACT:

9. HEREDOC NON-INTERACTIVE MODE FIX (src/exec/here_doc_stuff.c)
----------------------------------------------------------------
PROBLEM:
  Heredocs (<<) caused hangs when minishell ran in non-interactive mode
  (when commands piped to stdin). This broke both zstenger and other testers.

ROOT CAUSE:
  In non-interactive mode, heredoc content should be read during parsing,
  not during execution. The stdin is shared between the main command loop
  (which reads commands) and heredoc execution (which tries to read content).
  This causes:
  - get_next_line() to consume lines the main loop expects
  - Blocking reads waiting for input that's already been consumed
  - Race conditions in stdin buffer management

ARCHITECTURAL LIMITATION:
  Proper fix requires refactoring to read heredoc content during the 
  parsing phase. This is a significant architectural change.

WORKAROUND SOLUTION:
  Skip heredoc content reading in non-interactive mode (line 36-42):
  - Detect non-interactive mode with !isatty(STDIN_FILENO)
  - Create empty pipe for heredoc
  - Return success without reading content
  - Interactive mode still works normally with readline

TRADE-OFF:
  ✅ Prevents hangs in all testers
  ✅ Allows testers to complete (zstenger: 703/941 tests)
  ✅ Heredocs work perfectly in interactive mode (normal usage)
  ❌ Heredoc tests fail in non-interactive testers

IMPACT:
  - zstenger tester can now complete without hanging
  - LucasKuhn tester not affected (doesn't heavily test heredocs)
  - Interactive heredocs work as expected
