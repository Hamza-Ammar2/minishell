================================================================================
COMPREHENSIVE GUIDE: REFACTORING TO SEND QUOTE TYPES TO EXECUTOR
================================================================================

RESEARCHED APPROACHES FROM EXAMPLE CODE:
----------------------------------------

1. minishellclean approach:
   - Uses FRAGMENTS: breaks each word into single/double/unquoted fragments
   - Stores fragment metadata: type, start, end, spaces
   - Processes expansion PER FRAGMENT based on type
   - Very complex but handles mixed quotes like: echo"$HOME"'test'

2. minishell2 approach:
   - Stores quote type IN TOKEN TYPE: T_SQUOTE, T_DQUOTE, T_WORD
   - Expands during parsing BEFORE command creation
   - Parser calls expand_quotes() which processes based on token type
   - Simple but processes expansion early

YOUR APPROACH (RECOMMENDED):
---------------------------
You already have quote_type in s_token (QUOTE_NONE/SINGLE/DOUBLE).
Pass tokens with metadata to executor, let Hamza handle expansion.
This is SIMPLER and keeps parser/executor responsibilities separate.

```c
char **convert_tokens_to_argv(t_token **args, t_shell *shell)
{
	char	**argv;
	int		i;
	int		count;
	
	// Count args
	count = 0;
	while (args[count])
		count++;
	
	// Allocate argv
	argv = malloc(sizeof(char*) * (count + 1));
	if (!argv)
		return (NULL);
	
	// Process each token
	i = 0;
	while (args[i])
	{
		if (args[i]->quote_type == QUOTE_SINGLE)
		{
			// No expansion - use literal value
			argv[i] = ft_strdup(args[i]->value);
		}
		else if (args[i]->quote_type == QUOTE_DOUBLE)
		{
			// Variable expansion only (no wildcard)
			argv[i] = expand_variables(args[i]->value, shell->env);
		}
		else // QUOTE_NONE
		{
			// Full expansion (variables + wildcards)
			argv[i] = expand_all(args[i]->value, shell->env);
		}
		i++;
	}
	argv[i] = NULL;
	return (argv);
}
```

================================================================================

FINAL ARCHITECTURE FLOW
========================

1. USER INPUT: echo "$HOME" test
   ↓
2. TOKENIZER: Creates tokens with quote_type
   - Token 1: value="echo", quote_type=QUOTE_NONE
   - Token 2: value="$HOME", quote_type=QUOTE_DOUBLE
   - Token 3: value="test", quote_type=QUOTE_NONE
   ↓
3. PARSER: Creates t_command with t_token **args
   - cmd->args[0] = token pointer (echo, QUOTE_NONE)
   - cmd->args[1] = token pointer ($HOME, QUOTE_DOUBLE)
   - cmd->args[2] = token pointer (test, QUOTE_NONE)
   - cmd->args[3] = NULL
   ↓
4. EXECUTOR: Receives cmd and shell
   - Checks args[i]->quote_type for each arg
   - QUOTE_SINGLE: No expansion
   - QUOTE_DOUBLE: Variable expansion only
   - QUOTE_NONE: Full expansion
   - Creates char** argv for execve
   ↓
5. EXECUTION: execve with expanded argv

================================================================================

WHY THIS APPROACH IS BETTER THAN EXAMPLES:
===========================================

1. Separation of concerns:
   - Parser: structure only, no expansion
   - Executor: handles all expansion logic
   
2. Simpler than fragment approach:
   - minishellclean's fragment system is overkill for basic requirements
   - Your quote_type field is cleaner and easier to understand
   
3. Better than early expansion (minishell2):
   - Keeps original values intact through parsing
   - Executor can make decisions based on context
   - Easier to debug (can see original input)

4. Matches bash behavior:
   - Quote removal happens during execution, not parsing
   - Variable expansion context-aware
